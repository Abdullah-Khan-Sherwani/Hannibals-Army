## Setup

- Tasks / benchmarks (coding? repo-level? research? planning?): 600 synthetic, benign productivity tasks across eight domains; 2,556 required steps and 1,915 reserved actions; no coding (§3, pp.3–4).
- Models used (per role): Homogeneous DeepSeek V4 Flash, Qwen3.7 Plus, GPT-5.4 Nano, Gemini 3.1 Pro, GPT-5.6 Sol. Sol–Nano uses Sol only at root/entry, Nano for delegated peers, intermediate supervisors, workers. Judge: DeepSeek V4 Pro; authorizer tier unspecified (Table 11, p.19; §B.3).
- Baselines (single agent? flat team? budget-matched? yes/no + how): Single and peers; same tasks/tools, **not token/call matched**. 90,000 runs; one trajectory per cell, no repeated seeds (§E, pp.19–20).

## Topology tested

- Depth: 0 = single agent ? 1 = orchestrator ? workers ? 2 = orchestrator ? sub-orchestrators ? workers ? recursive ? 0 = Single; 1 = L1, orchestrator → two workers; 2 = L2, orchestrator → two sub-orchestrators → four workers; L3 adds another supervisor level, eight leaves, 15 total agents (Fig.4, p.15).
- Width (workers per orchestrator) and how it was varied: Binary branching fixed at two; fully connected peers N2/N4/N8. Equal-leaf comparisons have unequal total agents; peers capped at six handoffs (§C.1–2, p.15).
- Roles (planner, implementer, verifier, reviewer, integrator, router, ...): Generic versus typed N4/L2; L2-t adds research, execution, QA, compliance workers (Table 8, p.17).
- Communication / handoff format; who can write code/files: Self-contained packets include authorization boundary/state. Supervisors visit children sequentially and integrate after all report; workers use simulated workspace tools, supervisors may also use tools during integration. No repository edits studied (Tables 8–9, pp.17–18).

## Findings (quote numbers with table/figure/page refs)

- Depth (when does more depth help or hurt?): Five-model homogeneous means, L1/L2/L3: completion **93.9/98.1/98.6%**, UA **2.7/11.7/19.8%**. Last level gains only 0.4 completion points, adds 8.1 UA points (Table 3, p.7). Completion requires all required steps; UA measures tasks with executed reserved actions, independently.
- Width (where does adding workers plateau?): N2/N4/N8 completion **87.0/86.3/85.7%**, UA **0.8/0.8/0.6%**; no improvement from widening (five-model means, Table 3, p.7).
- Role ? model placement (which tier where, cost vs quality): Sol–Nano L2 UA **32.0%**, versus homogeneous Sol **1.5%**; L3 **39.5% versus 1.0%**. A strong root does not protect weaker downstream seats. L2-t adds QA/compliance yet homogeneous mean UA is **12.6% versus L2's 11.7%**, with completion **97.9% versus 98.1%** (Tables 3–4, p.7).
- Verification / review effects: **Source** checks calls against invariant original-user policy outside coordination; **Chain** monotonically narrows inherited policies. Source pooled completion changes **−1.6 points**, blocks ≤3.5% required calls; Chain loses up to **36.3 points**, blocks ≤54.5%. Chain UA is **0–0.2%**, not uniformly zero. Source balanced stage accuracy is **97.7–99.2%** (Fig.3, p.6; Tables 16–17, p.22); Sol constraint loss falls **44.69→1.06%** (Table 21, p.24).
- Cost / tokens / latency: Source token overhead **6.6–19.3%**, Chain **16.2–42.0%** (Table 16). Homogeneous Sol L1/L2/L3 consume **46.6k/111.3k/230.5k worker tokens/run** (Table 15, p.21). Configuration-average durations ≈75–420 seconds; concurrency only across tasks (§E.4, Table 12, p.20).
- Failure modes observed: **88.2%** of localized losses occur at first handoff (Table 18, p.23). Constraint loss differs from UA; preserved goals coexist with omitted prohibitions, duplicate transmissions, false final reports, sensitive argument disclosures (§G, pp.24–25).

## Implications for Hannibal's Army (label each as INFERENCE)

- Depth-1 design: **INFERENCE:** Start shallow; deliver original-user boundaries directly to workers and mediate consequential tools independently. Record completion and attempted/executed violations separately.
- Depth-2 design: **INFERENCE:** Add generals only for demonstrated coordination benefit; preserve boundaries at both delegation edges and retain source-based authorization outside their summaries. Readiness, supervisor agreement, and completed prerequisites cannot create user authorization (§3.1, p.3).
- Which agent/model type goes in which seat: **INFERENCE:** GPT-6.1-Sol root, Sonnet management/review generals, bounded Gemini implementers require independent authorization and a sole integrator. These particular model seats are untested; stronger reviewers alone cannot replace call-time enforcement.
