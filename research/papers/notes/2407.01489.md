## Setup
- Tasks / benchmarks (coding? repo-level? research? planning?): Repo-level coding — SWE-bench Lite (300 issues), plus manually filtered SWE-bench Lite-S (249) and SWE-bench Verified (500) in the journal version.
- Models used (per role): GPT-4o (gpt-4o-2024-05-13) for all LLM steps (localization prompts, repair, test generation); OpenAI text-embedding-3-small (chunk 512) for retrieval. No per-role routing (there are no agent roles).
- Baselines (single agent? flat team? budget-matched? yes/no + how): 26 agent-based baselines (open + closed source) + a RAG agentless baseline. Cost and token counts reported where available ⇒ comparison is roughly budget-aware: Agentless $0.70 / 78,166 tokens vs SWE-agent (Claude 3.5 Sonnet) 23.00% at $1.62 / 521,208 tokens, CodeR 28.33% at $3.34 / 323,802 tokens (Table 1, p.10).

## Topology tested
- Depth: 0 — deliberately agentless. No LLM decides future actions or uses complex tools; a fixed 3-phase pipeline (localization → repair → patch validation) with LLM calls at each step. Authors list the failure modes of agent-based depth-1 designs they avoid: complex tool usage/design errors, uncontrolled decision planning, limited self-reflection amplifying early mistakes (pp.2-3).
- Width (workers per orchestrator) and how it was varied: No workers; but candidate-parallelism at generation level: 4 edit-location samples × 10 patches = 40 candidate patches per issue; 40 reproduction-test samples (1 greedy + 39 sampled) (Implementation, p.9). Ablation varies sample counts (Fig 6, p.13): performance plateaus at ~40 patch samples.
- Roles (planner, implementer, verifier, reviewer, integrator, router, ...): No LLM roles; instead fixed stages: hierarchical localization (files → classes/functions via skeleton → edit locations), diff repair, and validation via generated reproduction tests + regression tests + normalized majority voting (the "verifier" is execution-based, not an LLM reviewer).
- Communication / handoff format; who can write code/files: All handoffs are structured artifacts: repository-structure tree, file skeleton (declarations only), Search/Replace diff format, reproduction test files with sentinel outputs ("Issue reproduced"/"Issue resolved"). Only sampled LLM outputs write files; selection is deterministic (AST-normalized majority vote).

## Findings (quote numbers with table/figure/page refs)
- Depth: Counter-evidence to complex autonomy: at publication, Agentless achieved the highest open-source SWE-bench Lite score (32.00%, 96/300) with "a much simpler design" (Table 1, §5.1, p.10) — but NOT the highest overall: closed-source CodeStory Aide 43.00%, MarsCode 39.33%, Honeycomb 38.33%, MentatBot 38.00% (Table 1, p.10). Where agents still win: problems with no location clue in the issue text (Fig 9c, p.17) — agent code-search tools help there.
- Width: 1 greedy sample per edit-location set already fixes ~80 issues; performance plateaus at 40 samples; considering all samples (not just one patch) the upper bound is 126/300 = 42.0% (Fig 6, p.13). Test-filtering + majority vote is what converts samples into wins.
- Role → model placement: N/A (single model). The interesting placement note: the verifier is not a model at all — it is generated tests executed against the repo, deliberately removing LLM judgment from the accept/reject decision ("different from agent-based approaches, which ... rely on an LLM agent to decide whether the test is correct", §2.3, p.5).
- Verification / review effects: Patch selection ablation (Table 4, p.14): majority voting only 77 (25.67%) → +regression tests 81 (27.00%) → +generated reproduction tests 96 (32.00%). So the verification stage contributes 19 of 96 fixes (+6.3 pts) over raw voting. But test quality is shaky: of 300 issues, 213 reproduction tests reproduced the bug, yet only 94 still reported "Issue resolved" after the ground-truth patch was applied (p.11) — generated verifiers are only ~44% trustworthy end-to-end; conservative fallback (regression tests must also pass; fall back to regression-only selection) mitigates this.
- Cost / tokens / latency: $0.70 avg and 78,166 average tokens per issue — below most agent baselines (e.g., SWE-agent $1.62/521K tokens, CodeR $3.34/324K; RAG $0.13-0.25 but solves 2.7-4.3%). Localization is cheap: file-level combined $0.06, related elements $0.02, edit locations $0.07 (Table 2, p.12).
- Failure modes observed: benchmark-quality failures dominate the frontier: 10.0% of SWE-bench Lite issues lack enough info, 4.3% contain the exact gold patch, 9.7% complete NL steps, 5.0% misleading solutions (Fig 8, pp.15-16). >10% of issues no location clue; when location clues exist (<10% line-level; ~50% file-level), Agentless matches closed-source agents. Multi-sample repair plateaus (majority voting ignores late samples). Reproduction tests often under-specified (213 reproduce vs 94 plausible).

## Implications for Hannibal's Army (label each as INFERENCE)
- Depth-1 design: (INFERENCE) Before adding a general/worker for every step, check whether a fixed pipeline of cheap calls does the job: hierarchical localization + diff generation + test-gated selection is a strong, cheap baseline for bounded fix tasks. The Army's worker specs should therefore require the worker's completion evidence to be execution artifacts (test output), not self-reported success — Agentless shows the biggest gain (25.67%→32%) comes exactly from executing generated repro tests plus regression tests.
- Depth-2 design: (INFERENCE) Agentless's plateau at ~40 candidate patches and its majority-vote integrator argue for bounded fan-out plus a deterministic merge rule (AST-normalized majority) instead of an LLM integrator seat for merge decisions on small tasks; reserve LLM integrators for semantic conflicts (the user's "sole integrator" role fits exactly there, not for picking among near-identical diffs).
- Which agent/model type goes in which seat: (INFERENCE) Verification seats should be execution-grounded and cheap-model-friendly (GPT-4o sufficed for test generation); don't spend top-tier model budget on verification of mechanical changes. Conversely, when the issue gives no location clue, strong agentic search (a capable implementer model with code-search tools) still beats agentless pipelines — so the user's strong-model seats pay off on hard localization, not on routine patching.
- Anti-pattern warning: (INFERENCE) Agentless's list (complex tool abstractions, unbounded action spaces, weak self-reflection) maps onto the user's observed general failures (generals settling early, stuck prompts); tight specs with fixed phases are a legitimate design for bounded tasks.

## Validity
- Evidence grade: A (peer-reviewed FSE 2025 journal version; extensive baselines; ablations with 6+ configurations; but older-generation numbers, see threats).
- Threats (contamination, not budget-matched, toy tasks, single model family, ...): GPT-4o contamination risk on SWE-bench gold patches acknowledged by authors (Threats, p.18); baselines are leaderboard-reported numbers from heterogeneous setups (different LLMs per tool), so cost/quality comparisons are approximate; single benchmark family (SWE-bench Lite/Verified, Python-only); closed-source baselines lack trajectories; results are from the 2024 GPT-4o era — by 2026 absolute numbers are dated, though the design lesson (execution-gated selection) persists; Agentless itself is now a component of the 2026 ecosystem (OpenAI used it as default SWE-bench showcase).
