## Topology tested
- Depth: 0 = single agent · 1 = orchestrator → workers · 2 = orchestrator → sub-orchestrators → workers · recursive: single-agent, star (closest to depth1), tree (hierarchical communication), chain and generic learned graphs. Tree baseline branching/command-layer details not reported here; do not label it a verified depth2 implementation. Three dialogue rounds are temporal iterations, not hierarchy levels.
- Width (workers per orchestrator) and how it was varied: five agents main;5/10/20 agents scaling (Table 6, p.15). Agent count is total graph size, not direct reports per manager; sparse design can omit irrelevant agents/edges.
- Roles (planner, implementer, verifier, reviewer, integrator, router, ...): task-specific profile pool; e.g. math analyst/solver/inspector or algorithm designer/programmer/test analyst/bug fixer/project manager (Figure 6, p.14). Roles held apart from graph-design module.
- Communication / handoff format; who can write code/files: directed edges carry prior responses plus original query in topological execution order; summarizer creates final answer after dialogue. Task virtual node is an embedding device, not an LLM chief. Programmer may generate/execute snippets; no exclusive files, permissions or merge protocol.

## Findings (quote numbers with table/figure/page refs)
- Depth (when does more depth help or hurt?): MMLU single82.14%, Star80.79%, Tree81.89%, complete83.15%, G-Designer84.50%; GSM8K single85.40%, Star85.55%, Tree84.56%, G-Designer95.07% (Table 1, p.7). A hierarchy shape alone does not guarantee improvement; no fixed-depth causal sweep.
- Width (where does adding workers plateau?): MMLU/GPT-3.5 G-Designer5→10→20 agents gives73.20→74.51→77.82%; prompt tokens452,329→885,332→1,852,538, runtime19.26→36.04→68.89min. GPTSwarm20 agents75.38%/30,317,341 tokens/412.18min (Table 6). No plateau by20 for learned sparse graphs; returns require extra compute.
- Role → model placement (which tier where, cost vs quality): homogeneous teams; no per-seat model-tier comparison. Small graph network can organize stronger LLM workers without itself being a large reasoning model.
- Verification / review effects: one-agent prompt attack: MMLU84.5→84.2; without sparsity84.1→83.2; without task node81.3→82.0. GSM8K95.0→92.5, versus90.3→87.7 without task node (Table 3, p.8). This tests topology robustness, not independent reviewer or centralized-verifier superiority.
- Cost / tokens / latency: GSM8K G-Designer95.0%,8.2M inference tokens,2.3h versus GPTSwarm89.7%,8.4M,2.8h; training0.27M tokens/0.3h versus5.5M/2.1h (Table 2, p.8). Large savings depend on comparator/task; do not universalize abstract's95.33%. Training graph-module memory at1,000 nodes is3.8GB (Table 5), NOT a1,000-worker end-to-end experiment.
- Failure modes observed: dense communication waste and prompt-attack propagation; easy biology Chain~0.5k versus GPTSwarm7.8k tokens with comparable accuracy, while harder college math benefits from richer structure (§1/Figure 2, p.2).

## Implications for Hannibal's Army (label each as INFERENCE)
- Depth-1 design: INFERENCE: remove irrelevant communication edges and retain task context in handoffs before adding workers.
- Depth-2 design: INFERENCE: make hierarchy conditional on dependency structure; these results do not establish that two command layers beat one.
- Which agent/model type goes in which seat: INFERENCE: lightweight topology selection and explicit summarization are plausible separate roles; model brands or stronger-only managers are unsupported here.
