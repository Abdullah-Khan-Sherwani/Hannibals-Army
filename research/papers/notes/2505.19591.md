## Topology tested
- Depth: 0 = single agent · 1 = orchestrator → workers · 2 = orchestrator → sub-orchestrators → workers · recursive: depth-1 controller repeatedly activates workers; their interaction graph can contain cycles, self-loops and cross-branch links. Paper's depth = reasoning-chain length, NOT command hierarchy; no direct depth-2 management test (§2.1, p.3; §3.4, p.9).
- Width (workers per orchestrator) and how it was varied: exploration trajectories varied in Figure 7: W4D2, W4D3, W6D2. Implementation prose instead says episode length4/parallel exploration3 (p.5); report inconsistency rather than equating either with recommended worker fan-out.
- Roles (planner, implementer, verifier, reviewer, integrator, router, ...): planner, reasoner, critic, reflector, questioner, summarizer, concluder, modifier, terminator, tool users (Table 2, p.22; prompts pp.24–28).
- Communication / handoff format; who can write code/files: policy observes global task state, selects next agent, updates shared state and aggregates outputs (majority voting). Reasoning result/final-answer templates; tool calls use JSON action/parameter. Python agents execute code; FileAgent reads. No exclusive file or merge ownership protocol.

## Findings (quote numbers with table/figure/page refs)
- Depth (when does more depth help or hurt?): Figure 7 (p.9) W4D2 accuracy0.305/tokens2,678.850 versus W4D3 0.290/6,037.950: longer reasoning loses1.5pp while costing ~2.25×. The figure does not identify a benchmark; do not generalize its optimum.
- Width (where does adding workers plateau?): same figure W6D2 accuracy0.265/tokens3,164.349 versus W4D2 0.305/2,678.850: wider exploration loses4pp and raises tokens~18%. No evidence for a universal maximum width.
- Role → model placement (which tier where, cost vs quality): evolved Titan heterogeneous average0.7731 versus Mono405B0.7453; Mimas0.6324 versus Mono8B0.6147 (Table 1, p.6). Pool composition and search space change together; does not isolate any model's suitability for a particular seat.
- Verification / review effects: Figure 6 (p.8) graph-density mean1.0829→1.4479 and more cycles accompany learning; critique/reflection reuse is observational, not a causal verifier ablation. Recurrence is not recursive delegation.
- Cost / tokens / latency: stronger Titan agents tend to terminate earlier; Mimas savings more often arise from lower-cost selections (§3.2, p.7). Orchestrator training uses8 A800 GPUs,2–6h,28.8–78.4GB/GPU (Table 3, p.22); no comprehensive latency comparison.
- Failure modes observed: redundant over-expansion, coarse final rewards, fixed agent/tool pool, occasional miscoordination/deceptive agreement (Appendix D, pp.22–23). Some settings show no clear efficiency improvement (Appendix A).

## Implications for Hannibal's Army (label each as INFERENCE)
- Depth-1 design: INFERENCE: permit bounded critique/revision loops and early termination; keep only workers with measured marginal contribution.
- Depth-2 design: INFERENCE: this supports feedback within a command hierarchy, not adding management layers; separately compare depth1/2 under equal total tokens.
- Which agent/model type goes in which seat: INFERENCE: evaluate coordinator selection/stopping skill separately from implementation skill; do not derive GPT/Claude/Gemini brand assignments from pooled averages.
