## Topology tested
- Depth: 0 = single agent · 1 = orchestrator → workers · 2 = orchestrator → sub-orchestrators → workers · recursive: learned DAG of agentic operators, max L=4 workflow stages with early exit. Operators may internally contain multiple agents. This is computational nesting, not a controlled depth1/2 management-tree comparison (§3.1–3.2, p.4).
- Width (workers per orchestrator) and how it was varied: variable operators per stage selected until cumulative activation score exceeds0.3; K=4 training architecture samples, distinct from live worker width. Debate operator initializes3 debaters×2 rounds, self-consistency5 paths, ensemble3 agents (Appendix B.1, p.13). No isolated worker-count sweep.
- Roles (planner, implementer, verifier, reviewer, integrator, router, ...): learned architecture controller; CoT solver, debater, self-refiner, ensemble ranker, test generator, ReAct tool user, early-exit node.
- Communication / handoff format; who can write code/files: operator DAG passes generated outputs; operators combine LLM calls, prompts and tools. Textual gradient modifies Python operator definitions and prompts through JSON thought/description/code (§3.3; Appendix B.3). No sole-integrator or file-ownership experiment.

## Findings (quote numbers with table/figure/page refs)
- Depth (when does more depth help or hurt?): increasing maximum workflow layers2→4 raises reported performance89.5→92.8%; further layers yield marginal gains and higher cost (Figure 7/§4.5, p.8). This is workflow depth, not evidence that two management layers win.
- Width (where does adding workers plateau?): no worker fan-out optimum established. K=2 gives higher-variance/suboptimal gradient estimates; K=4 is sufficient in sensitivity study (§4.5). Do not translate K into four workers per orchestrator.
- Role → model placement (which tier where, cost vs quality): no mixed-tier seat ablation. Same supernet transfers HumanEval85.60→90.14 for Qwen and80.06→85.26 for Llama; MATH31.93→42.97 for Llama (Table 7, p.18). Supports transferable workflow design, not a brand hierarchy.
- Verification / review effects: removing early exit changes HumanEval92.85→91.44 while cost rises1.01→1.67 millidollars/query; MATH51.82→51.53, cost0.86→1.04. Removing cost penalty yields HumanEval92.94 at1.38 and MATH51.19 at1.28 (Table 4, p.8). Testing/refinement activation increases in deeper layers (Figure 10); no isolated reviewer-correctness test.
- Cost / tokens / latency: MATH AFlow accuracy51.28 versus MaAS51.82; training cost$22.50→$3.38, time184→53min; inference$1.66→$0.42, time23→19min, prompt/completion tokens2,505,944/2,151,931→1,311,669/853,116 (Table 3, p.7). Aggregate dataset runs, not per-task latency.
- Failure modes observed: fixed complex workflows waste computation on easy tasks; aggressive early stopping can underexplore; removing operator adaptation lowers MATH51.82→48.23 (Table 4).

## Implications for Hannibal's Army (label each as INFERENCE)
- Depth-1 design: INFERENCE: make cheap paths and early stopping explicit; add specialist/review work when measured task difficulty warrants it.
- Depth-2 design: INFERENCE: keep a cap and compare total cost as well as quality; L=4 is not a recommendation for four organizational tiers.
- Which agent/model type goes in which seat: INFERENCE: repeatable workflow selection may need only a small learned controller; reserve an LLM designer for changing workflows. No evidence for specific current vendor seats.

## Validity
- Evidence grade: A = peer-reviewed + controlled · B = preprint + controlled · C = case study / uncontrolled: A, ablations and measured cost with imperfect controls.
- Threats (contamination, not budget-matched, toy tasks, single model family, ...): public small benchmarks; dataset-specific optimization; no full equal-compute depth comparison; training uses benchmark subsets; manuscript inconsistencies (MATH617 stated versus605 listed, dataset names/counts and Blender backbone).
