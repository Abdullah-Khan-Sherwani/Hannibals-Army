## Setup
- Tasks / benchmarks: Benchmark of 2,400 multi-step agent trajectories (600 per domain, 4–12 steps per trajectory, totaling 18,720 step-level decisions) across four domains: document analysis, code generation, research synthesis, and data analysis; Section 4.1, p. 3.
- Models used (per role):
  * Tier 1 (Frontier): GPT-4o / Claude Opus-class ($15–$30/M output tokens) — planning, complex multi-hop reasoning, architecture design.
  * Tier 2 (Mid-range): GPT-4o-mini / Claude Sonnet-class ($2.40–$8/M output tokens) — code generation, multi-file synthesis.
  * Tier 3 (Efficient): Llama-3-70B-Instruct ($0.50–$2/M output tokens) — document synthesis, tool extraction.
  * Tier 4 (Minimal): Llama-3-8B-Instruct ($0.05–$0.20/M output tokens) — formatting, retrieval lookup, JSON validation.
- Baselines: (1) Frontier-only baseline (all steps to GPT-4o); (2) RouteLLM applied per-step; (3) FrugalGPT cascade adapted to 4 tiers; (4) DAAO (Difficulty-Aware Agentic Orchestration); (5) Budget-Aware Agentic Routing; Table 1, p. 4.

## Topology tested
- Depth: 1 (Orchestrator routes sequential multi-step execution steps $\tau = (s_1, \dots, s_T)$ to heterogeneous worker models; Section 3.1, p. 2).
- Width: Sequential multi-step trajectories (4 to 12 steps); routing decisions executed step-by-step with dependency-aware context updating ($f_{ctx}$); Section 3.2–3.3, p. 2–3.
- Roles: Step-level functional roles categorized by task type $f_{type} \in \{\text{PLAN}, \text{REASON}, \text{RETRIEVE}, \text{GENERATE}, \text{FORMAT}, \text{VERIFY}\}$; Section 3.2, p. 2.
- Communication / handoff format; who can write code/files: Trajectory context accumulator: step $t$ output updates context vector for step $t+1$; 12M-parameter feedforward classifier (<5ms latency on A100 GPU) evaluates 5 extractable features ($f_{type}, f_{depth}, f_{tool}, f_{format}, f_{ctx}$) to map each step to model tiers 1–4; Section 3.2–3.3, p. 2–3.

## Findings (quote numbers with table/figure/page refs)
- Depth: Step-level routing across multi-step agent trajectories achieves 71.8% cost reduction relative to uniform frontier execution while preserving 97.3% of frontier-only end-to-end task quality (<3% degradation; Table 1, p. 4).
- Width: In enterprise agent trajectories, 55%–70% of steps require no frontier model capability (Section 1, p. 1). Only 14.2% of steps genuinely require Tier 1 (Frontier) models, yet those 14.2% consume 48.3% of the remaining inference budget (Table 2, p. 4). Tier 4 handles 35.3% of all steps for only 10.8% of the cost.
- Role → model placement:
  * Initial planning and multi-hop reasoning require Tier 1 (Frontier, e.g. GPT-4o/Opus).
  * Implementation/generation requires Tier 2 or Tier 3 (Sonnet / 70B). In code generation, 26.3% of steps require Tier 1 reasoning (vs 8.7% in document analysis), resulting in lower but still substantial 63.8% cost reduction (Section 4.4, p. 4).
  * Context extraction, formatting, JSON validation, and straightforward retrieval require only Tier 4 (Minimal, 8B class) with 91.2% routing accuracy (Table 2, p. 4).
  * Single-turn routers fail in agent workflows: RouteLLM applied per-step achieves only 31.4% cost reduction (94.2% quality) and FrugalGPT achieves 44.1% cost reduction (with 48ms latency overhead), because treating steps independently ignores how poor intermediate outputs corrupt context for subsequent steps (Section 1, p. 1; Table 1, p. 4).
  * Feature importance: Task type $f_{type}$ provides the strongest routing signal (-12.3 accuracy drop when removed, reducing cost savings to 54.2%), followed by reasoning depth $f_{depth}$ (-7.1) and context utilization $f_{ctx}$ (-4.8; Section 4.4, p. 4).
- Verification / review effects: Verifying format constraints and output schemas ($f_{format}$) is safely assigned to Tier 4 (8B) models without quality loss; semantic verification with cross-document consistency requires Tier 2/3 (Section 1, p. 1; Section 3.2, p. 2).
- Cost / tokens / latency: AgentRouter adds only 4.7ms latency per step on an A100 GPU (vs 48ms for FrugalGPT cascade and 22ms for DAAO; Table 1, p. 4). Median model tier switches per trajectory is 3.2 (Section 5, p. 5).
- Failure modes observed: (1) Single-turn routers misclassifying intermediate steps because they lack trajectory context accumulation; (2) Trajectory-level optimizers (like DAAO) over-provisioning every step based on the single hardest step, saving only 36.2% cost; (3) Cascading quality degradation when an under-provisioned Tier 4 model corrupts intermediate state passed to downstream frontier models (mitigated by asymmetric loss penalty $\lambda = 0.3$ and automated fallback; Section 3.3, p. 3).

## Implications for Hannibal's Army (label each as INFERENCE)
- Depth-1 design: INFERENCE: An orchestrator should never deploy frontier models for formatting, git status checking, JSON generation, or retrieval queries; delegating these routine steps to fast/cheap models (Gemini Flash / 8B) slashes token spend by over 70% with less than 3% quality loss.
- Depth-2 design: INFERENCE: In a two-tier hierarchy (Field Marshal → Generals → Soldiers), Generals must not route entire task workflows to a single model tier; rather, Generals should segment subtasks into planning/reasoning phases (assigned to Sonnet/Opus) and execution/formatting phases (assigned to Flash/cheap workers).
- Which agent/model type goes in which seat:
  * High-Level Architectural Planning / Root Reasoning: Tier 1 (Frontier: GPT-6.1-Sol / Opus) — ~14% of total steps.
  * Routine Implementation / File Editing: Tier 2 (Sonnet / GPT-4o-mini).
  * File Reading, Tool Formatting, Status Checking, Verification of JSON/Diff Syntax: Tier 4 (Gemini Flash / 8B–14B) — ~35% of total steps.
  * Fallback Gate: INFERENCE: Implement a barrier validation check where any step failing schema or syntax verification triggers immediate frontier re-execution rather than letting corrupted state cascade to the next worker.

## Validity
- Evidence grade: A (Peer-reviewed workshop paper at ICML 2026; tested on 2,400 held-out trajectories across 4 diverse domains with 18,720 step decisions, ablation studies, and wall-clock latency benchmarking).
- Threats: Assumes trajectory steps can be tagged or templated at execution time; evaluation does not cover dynamic open-ended multi-agent debates where steps are completely unscripted.
