# 2505.20182 — An Empirical Study on Strong-Weak Model Collaboration for Repo-level Code Generation

- Title / authors / first arXiv date / latest version: "An Empirical Study on Strong-Weak Model Collaboration for Repo-level Code Generation" / Shubham Gandhi, Atharva Naik, Yiqing Xie, Carolyn Rose / 26 May 2025 / arXiv:2505.20182v1

## Setup
- Tasks / benchmarks: SWE-bench Lite (300 real-world GitHub issues across 11 Python repositories; Section 4, p. 3).
- Models used (per role):
  * Strong models: OpenAI o3-mini (high reasoning effort), o4-mini (high reasoning effort), GPT-4o-mini (when paired with local models); Section 4, p. 3; Table 1, p. 7.
  * Weak models: GPT-4o-mini, Qwen2.5-Coder-7B, Qwen2.5-Coder-14B, Qwen2.5-Coder-32B; Section 4, p. 3; Table 1, p. 7.
- Baselines: 14 collaborative and standalone techniques across 4 categories: (1) Cost-equated weak-only baselines (Majority Voting $SC_m$, Clustering $SC_c$, Universal $SC_u$, Best of $n$); (2) Static Context Augmentation (Repo Summary, Repo FAQs, Repo Structure, 1-shot/5-shot Few-Shot, Instance-Level Planning, Instance QA); (3) Pipeline Division (Strong LM First, Weak LM First, Prompt Reduction); (4) Dynamic Collaboration (Weak Router, Strong Router); Section 3, p. 2–3.

## Topology tested
- Depth: 1 (Two-stage collaborative pipeline: Stage 1 [Context/Plan/First Attempt/Routing] → Stage 2 [Refinement/Repair/Execution]; Section 3, p. 2–3; Figure 1, p. 2).
- Width: Fixed 1-to-1 or sequential handoff (1 strong model paired with 1 weak model, or sampled weak iterations $n$ matching strong cost; Section 3 & 4, p. 2–3).
- Roles: Planner/Context Provider (strong model), Implementer/Generator (weak model), Patch Formatter/Refiner (weak model), Router (weak or strong model).
- Communication / handoff format; who can write code/files: Textual context handoff (plan or initial patch passed via prompt) inside Agentless-Lite; code generation and iterative SEARCH/REPLACE diff formatting handled by the designated model in the pipeline (Section 3, p. 2–3).

## Findings (quote numbers with table/figure/page refs)
- Depth: Two-stage strong-weak pipelines significantly outperform single-model execution on cost-efficiency frontiers: Strong LM First (strong generates code logic, weak iteratively refines patch formatting) matches strong solo accuracy while cutting cost by ~40% (Section 1, p. 1–2; Section 5, p. 4).
- Width: Scaling weak model sampling width to match strong model budget (Cost-equated baselines: 15× to 78× repeated samples) fails catastrophically: $SC_m$ and $SC_c$ for GPT-4o-mini achieve only 0.1433–0.1500 resolution (below base 0.1533) despite burning $35.307 (matching O4-mini cost); for Qwen-7B, repeated sampling costs $46.090 to achieve a dismal 0.0700 resolution (Table 3, p. 14; Table 5, p. 15).
- Role → model placement:
  * Strong LM First (Strong Architect/Coder → Cheap Formatter/Patcher): With O3-mini + Qwen2.5-Coder-32B, Strong LM First achieves 0.3300 resolution rate (matching solo O3-mini at 0.3367) while cutting total cost from $46.224 to $27.737 (a 40% cost reduction; Section 1, p. 1; Table 7, p. 16). With O4-mini + GPT-4o-mini, it achieves 0.4167 (recovering 92% of O4-mini's 0.4533) at $25.341 vs $33.328 (Table 3, p. 14).
  * Strong Instance Planner → Cheap Implementer: Having the strong model generate an instance-specific natural language plan boosts weak GPT-4o-mini resolution from 0.1533 to 0.2933 (+91% relative increase; Table 3, p. 14).
  * Repo-level context hurts weak implementers: General repo summaries, repo FAQs, and few-shot examples fail to improve or degrade weak model resolution (e.g. 5-shot similarity drops GPT-4o-mini from 0.1533 to 0.1367; Table 3, p. 14).
  * Weak Router outperforms Strong Router: Counterintuitively, Weak Router frequently beats Strong Router in both resolution and cost (Section 5.1, p. 4). On O4-mini + GPT-4o-mini, Weak Router achieves 0.2400 resolution at $17.903, whereas Strong Router achieves 0.2133 at $36.342 (Table 3, p. 14). Strong models "overthink" simple routing decisions.
- Verification / review effects: Format verification and syntax repair do NOT require expensive reasoning models; weak models handle format repair effectively when initialized with strong model drafts (Strong LM First achieves 0.960 valid patch rate; Table 3, p. 14).
- Cost / tokens / latency: Pipeline methods show the highest average efficiency in ANOVA analysis ($p < 0.00001$; Section A.4, p. 12; Table 2, p. 13). Weak LM First is optimal under ultra-low budgets (<$10 total), while Strong LM First dominates higher-budget regimes (Section 5, p. 4; Figure 2, p. 3).
- Failure modes observed: (1) Cost-equated repeated sampling of weak models suffers from selection collapse (cannot identify the correct patch among 20–80 noisy samples); (2) Strong routers wasting reasoning budget and overthinking routing classifications; (3) Repo-level background summaries acting as distractors that dilute weak models' attention on localized code fixes.

## Implications for Hannibal's Army (label each as INFERENCE)
- Depth-1 design: INFERENCE: In an Orchestrator → Worker setup, the orchestrator should generate precise instance-level plans or high-level logic drafts rather than generic repo-level overviews; weak workers can then implement and format patches without degrading accuracy.
- Depth-2 design: INFERENCE: Routing between Generals (sub-orchestrators) and Workers should be governed by fast/cheap classification (matching Gandhi's Weak Router finding) rather than long chain-of-thought routing prompts that burn tokens and overthink task delegation.
- Which agent/model type goes in which seat:
  * Problem Localization & First Logical Draft: Strong frontier tier (O3/O4/Opus/Sonnet) to establish the correct fix trajectory.
  * Formatting, Patch Syntax & Repetitive Refinement: Cheap tier (GPT-4o-mini / Gemini Flash / Qwen-32B), saving up to 40% of inference spend.
  * Router / Task Dispatcher: Fast/cheap classifier tier (Weak Router) rather than heavy frontier models.
  * What to avoid: Never attempt to compensate for a weak model by running repeated majority voting (Best-of-N / self-consistency); it inflates cost to frontier levels while failing to solve complex repo tasks.

## Validity
- Evidence grade: A (Peer-reviewed conference paper, published at EMNLP 2025; systematic ANOVA analysis across 14 methods, 6 model pairs, 300 real-world benchmark issues).
- Threats: Evaluated within the Agentless-Lite paradigm (retrieval + iterative generation) rather than free-form agentic terminal tool-use; testbed limited to Python repositories on SWE-bench Lite.
