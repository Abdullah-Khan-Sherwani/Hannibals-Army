## Setup
- Tasks / benchmarks: EntBench (54 enterprise multi-step tasks across seven classes: SQL-Gen, Mongo-Gen, Extract, SQL-Compose, Cross-Recon, MultiTool-Plan, Policy-Action; graded by executing generated queries against live PostgreSQL 15 and MongoDB 8.0 databases; Table I, p. 3; Section IV, p. 3).
- Models used (per role):
  * Planner: Claude Haiku 4.5 (`claude-haiku-4-5-20251001`, small tier, held fixed across all routers; Section III-A, p. 2).
  * Specialist Tiers: Small = Claude Haiku 4.5 ($1/$5 per M tokens); Mid = Claude Sonnet 4.6 ($3/$15 per M tokens); Frontier = Claude Opus 4.7 ($5/$25 per M tokens); Section III-A, p. 2.
- Baselines: (1) AllFrontier (all nodes to Opus 4.7); (2) AllSmall (all nodes to Haiku 4.5); (3) SinkFrontier (frontier on terminal/sink nodes only, small elsewhere); (4) SourceFrontier (frontier on root nodes only, small elsewhere); (5) FrugalGPT cascade (small first, escalating on low scorer confidence); (6) PaR-Lite (Haiku binary classifier short-circuiting planner); (7) PaR-no-rationale ablation; Table II, p. 4.

## Topology tested
- Depth: 1 (Planner decomposes query into subtask DAG, assigns tiers, and dispatcher executes nodes in topological dependency order; Section III, p. 2–3).
- Width: Averaging 1.8 subtasks per plan (varying from 1.0 on single-step capability tasks to 3.3 on MultiTool-Plan; Table V, p. 5).
- Roles: Planner (runs on cheap small tier with forced structured JSON tool call `produce_plan`), Specialist Workers (`sql_gen`, `mongo_query`, `extract`, `cross_recon`, `multitool_plan`, `policy_action`), Dispatcher (manages topological execution, error propagation, and bounded single-tier retry/escalation).
- Communication / handoff format; who can write code/files: Subtask DAG handoff; upstream node execution output passed as context to downstream consumers ($u \to v$); specialists execute tool calls against database backends; Algorithm 1, p. 3.

## Findings (quote numbers with table/figure/page refs)
- Depth: Decomposing tasks into a dependency DAG with plan-time tier routing cuts inference cost by 44% against AllFrontier ($0.0101 vs $0.0182 per task) while giving up only 2.9 percentage points of accuracy (26.1% vs 29.0%; Table III, p. 5).
- Width: Subtask width scales with complexity (Table V, p. 5). Single-step capability tasks stay at 1.0 subtasks, whereas multi-source reconciliation averages 2.8 subtasks and multi-tool planning averages 3.3 subtasks.
- Role → model placement:
  * Planning can run on cheap models: Running the planner on small-tier Haiku 4.5 with forced structured schema and required rationale successfully places PaR on the optimal cost-accuracy Pareto frontier (Section III-A, p. 2; Figure 3, p. 5).
  * Leaf and retrieval steps belong in cheap tiers: PaR routes single-source reads and simple extractions to small tier (SQL-Gen 75% small, Mongo-Gen 88% small, Extract 95% small; Table V, p. 5).
  * High fan-in and reconciliation nodes belong in mid/frontier tiers: Subtasks whose outputs are consumed by multiple downstream tasks are automatically assigned to Sonnet or Opus (Cross-Recon routes 55% mid, 19% frontier; SQL-Compose routes 78% mid, 10% frontier; Table V, p. 5).
  * Overall tier distribution: PaR's measured plan mix across 162 runs is 45% small, 46% mid, and 8% frontier (Section V, p. 3).
  * Outperforms per-call cascades: PaR beats FrugalGPT in both accuracy (26.1% vs 23.2%, +2.9 pp) and cost ($0.0101 vs $0.0113, -12% cost), because per-call cascades evaluate nodes in isolation and fail to foresee dependency compounding (Table III, p. 5).
  * Cost-rationale ablation: Removing the required `cost_rationale` string field from the planner schema collapses Cross-Recon accuracy from 12.5% to 0% at >4× the cost, proving that forcing the planner to explicitly justify tier assignment is load-bearing (Section VIII-A, p. 6).
- Verification / review effects: Controlled retry policy: subtasks retry at assigned tier up to 3 times before escalating exactly one tier once; bounding escalation prevents every router from collapsing onto expensive frontier models while preserving robustness (Algorithm 1, Section III-C, p. 2–3).
- Cost / tokens / latency: PaR delivers 1.6× the accuracy-per-dollar of AllFrontier and 1.3× that of SinkFrontier under utility metric $U = A/C^\alpha$ at $\alpha=1$ (Section VII, p. 4–5).
- Failure modes observed: (1) Compounding errors along dependency chains: when cheap models fail upstream, error propagates to downstream nodes, producing a compounding factor $\rho = 3.33$ in a pilot sweep (vs $\rho = 1.27$ for AllFrontier; Table VI, p. 6; Figure 4); (2) Unfaithful baseline cascades that silently collapse onto small-tier behavior if confidence scores are uncalibrated (Section VI, p. 4).

## Implications for Hannibal's Army (label each as INFERENCE)
- Depth-1 design: INFERENCE: Model routing must happen during planning before worker dispatch, not as a downstream reactive cascade. When decomposing tasks, the Orchestrator must assign model tiers based on DAG topology (high fan-in tasks requiring mid/strong models, leaf data-fetching tasks assigned to cheap models).
- Depth-2 design: INFERENCE: Generals (sub-orchestrators) must require structured JSON plan contracts containing an explicit `cost_rationale` field; omitting this justification causes tier selection to collapse on compositional multi-step tasks (matching PaR's finding where removing rationale dropped Cross-Recon to 0%).
- Which agent/model type goes in which seat:
  * Planner / DAG Constructor: Fast, strict schema-following model (Haiku / Gemini Flash / Sonnet) using cached prompts and forced structured tool calling.
  * Root/Leaf Data Retrieval Workers: Cheap tier (Haiku / Gemini Flash) — accounts for ~45% of total subtasks.
  * High Fan-in Fusion / Reconcilers / State Mergers: Mid tier (Sonnet / GPT-4o-mini) — accounts for ~46% of subtasks.
  * High-Risk / Ambiguous Policy Decision Workers: Frontier tier (Opus / Sol) — reserved strictly for ~8% of critical bottleneck subtasks.
  * Escalation Policy: INFERENCE: Limit retry escalation to at most one tier up (e.g., Flash → Sonnet) after $\le 3$ retries to prevent runaway token spend.

## Validity
- Evidence grade: A (Peer-reviewed conference paper, accepted at AIxSET 2026; 1,157 evaluations across 8 routers, 3 seeds, graded against live SQL/Mongo databases, paired bootstrap 95% CIs).
- Threats: 54 tasks in benchmark yield relatively wide confidence intervals (±6 pp); compounding analysis ($\rho=3.33$) was measured in a 21-task pilot rather than full benchmark sweep.
