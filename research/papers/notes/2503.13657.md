## Setup
- Tasks / benchmarks (coding? repo-level? research? planning?): Mixed: coding (ProgramDev / ProgramDev-v2 — synthesized 30/100-program tasks; SWE-Bench Lite), math (GSM-Plus, GSM8K-style, OlympiadBench, MMLU), general agent (GAIA, AppWorld Test-C, Test-C). Includes both repo-level (SWE-Bench Lite via HyperAgent) and greenfield coding. Traces: 1642 annotated (Table 1, p.3). Failure defined as "MAS does not achieve its intended task objectives"; task completion checked by humans (HE) for 18 configurations.
- Models used (per role): GPT-4, GPT-4o, GPT-4o-mini, Claude-3.7-Sonnet across 7 frameworks (ChatDev, MetaGPT, HyperAgent, AppWorld, AG2/MathChat, Magentic-One, OpenManus); open-source comparison with Qwen2.5-Coder-32B and CodeLlama-7b (Table 6, p.29). Annotation pipeline uses OpenAI o1 (few-shot).
- Baselines (single agent? flat team? budget-matched? yes/no + how): Not a performance paper — no budget-matched teams-vs-single comparison. It measures failure rates of existing MAS (41%–86.7% failure on 7 SOTA open-source MAS, Fig 5 p.19) and intervenes within the same system/model (same user prompt + GPT-4o) in case studies (Table 5, p.27).

## Topology tested
- Depth: Assorted real system topologies, not varied by the authors: hierarchical workflows (ChatDev, HyperAgent with Planner → Navigator/Editor/Executor child agents, OpenManus), assembly-line (MetaGPT), star topology (AppWorld supervisor ↔ per-service agents; Magentic-One). Sub-agent depth exists in HyperAgent (Planner coordinates child agents) but no depth ablation.
- Width (workers per orchestrator) and how it was varied: Not varied. Width appears implicitly: HyperAgent publishes subtasks to queues where multiple Navigator/Editor/Executor instances process tasks asynchronously in parallel (Appendix B.2, p.19-20); AppWorld 1 supervisor ↔ N service agents in one-on-one multi-turn conversations.
- Roles (planner, implementer, verifier, reviewer, integrator, router, ...): MetaGPT: Coder + Verifier; ChatDev: CEO, CPO, CTO, Programmer, Reviewer, Tester (3 phases: design, coding, testing with code review + system testing); HyperAgent: Planner, Navigator, Code Editor, Executor; AppWorld: supervisor + service-specialized agents; AG2 case study adds Problem Solver + Coder + Verifier (only verifier can terminate, Appendix H.1, p.26).
- Communication / handoff format; who can write code/files: Natural-language conversation traces; HyperAgent uses standardized message fields Context + Request published to per-role queues; ChatDev pairs an orchestrator + assistant per sub-task with sentinel-based termination; AG2 termination controlled by the Verifier role. No global file-write protocol (systems own their repos/code).

## Findings (quote numbers with table/figure/page refs)
- Depth: No depth ablation. Failure categories by prevalence across 1642 traces (Fig 1, p.2): System Design Issues 44.2%, Inter-Agent Misalignment 32.3%, Task Verification 23.5% (a 210-trace subset: 41.8 / 36.9 / 21.3, Fig 4/Sec 5 header, p.8). Most common single modes: Step Repetition 15.7%, Reasoning-Action Mismatch 13.2%, Unaware of Termination Conditions 12.4%, Disobey Task Spec 11.8% (Fig 1).
- Width: No width sweep. System-specific profiles in Fig 4 (p.8): AppWorld (star topology, no predefined workflow) suffers premature termination (FM-3.1); OpenManus and HyperAgent suffer step repetition (FM-1.3); "no one-size-fits-all solution to MAS failures."
- Role → model placement: No routing experiments. Comparative (Fig 8-9, App F, pp.22-24): in MetaGPT, GPT-4o has ~39% fewer FC1 failures than Claude-3.7-Sonnet; FC3 (verification) stays high for both models — verification weakness is model-independent. MetaGPT vs ChatDev (same GPT-4o, ProgramDev-v2): MetaGPT has 60-68% fewer FC1/FC2 failures but 1.56x more FC3 failures; authors attribute this to ChatDev's explicit testing/review phases vs MetaGPT's SOP-driven roles.
- Verification / review effects: Insight 3 (p.8): "Multi-Level Verification is Needed"; sole final-stage low-level checks are inadequate. Systems with explicit verifiers (MetaGPT, ChatDev) show fewer total failures (Fig 4) but "the presence of a verifier is not a silver bullet" — ChatDev chess program passed compile-style review yet failed actual game rules (FM-3.2, p.8); GT analysis found verifiers checking only compile success/TODO leftovers "despite being prompted to perform thorough verification."
- Cost / tokens / latency: Only annotator costs: LLM-as-judge average $1.8/trace (Table 9, p.30; $0.37-$4.14 across frameworks). No agent-side token/cost accounting.
- Failure modes observed: The taxonomy itself. 14 modes in 3 categories (Fig 1/A). Fatal vs non-fatal (Table 7, p.29): FM-1.5 Unaware of Termination Conditions and FM-2.4 Information Withholding appear almost exclusively in failed runs; verification failures (FM-3.2/3.3) appear frequently even in successful runs (systemic weakness masked by task success). Successful runs are not failure-free. Intervention results (Table 5, p.27): AG2 GSM-Plus (GPT-4) baseline 84.75→89.75 improved prompt→85.50 new topology (topology n.s., Wilcoxon p=0.4; GPT-4o p=0.03 for both); ChatDev ProgramDev-v0 25.0→34.4 prompt→40.6 topology (=+15.6 pts, cited as "+15.6%" p.8 §5.3); HumanEval 89.6→90.3→91.5. Role-specification fix in ChatDev alone: +9.4% success (p.3). Topology-based (DAG→cyclic, terminate only when CTO confirms all reviews, max-iteration cutoff) beat prompt-based changes (H.3, p.27). Inter-annotator agreement κ=0.88; LLM annotator (o1 few-shot) accuracy 94%, κ=0.77 (Table 2, p.6); generalization κ=0.79 on unseen MAS (p.6).

## Implications for Hannibal's Army (label each as INFERENCE)
- Depth-1 design: (INFERENCE) Directly backs the user's STATUS-gate and reviewer-audit rules. MAST says field-marshal-style supervision must guard FM-1.5 (unaware of termination: 12.4% of all failures) with explicit, objective termination conditions — the user's "observed turn start / ack every delivery / one waiter" and "worker_done is the only completion signal" are exactly the fix. Also FM-1.3 step repetition (15.7%): orchestrators should detect repeated tool/file edits, which a general watching STATUS.md would catch.
- Depth-2 design: (INFERENCE) MAST's data suggests sub-orchestrators add another conversation layer where FC2 misalignment (32.3%) lives — the collapse of "theory of mind" between agents. Keep messages self-contained with explicit Context+Request fields (HyperAgent-style) and make only one seat (a verifier/general) able to terminate a loop (AG2 H.1 fix), to prevent midpoint sub-orchestrators derailing or terminating early.
- Which agent/model type goes in which seat: (INFERENCE) Verification is model-independent in MAST (FC3 stays high across GPT-4o and Claude 3.7) — so a stronger model alone won't fix weak review; verification must be structural (multi-level: low-level checks + high-level objective check). This supports the user's separate read-only reviewer seats over "same worker double-checks itself". Planner/orchestrator seats get instruction-following-strong models (GPT-4o had 39% fewer FC1 failures than Claude in MetaGPT); the cheap-worker/strong-verifier split in Hannibal's Army is consistent with MAST showing coordination and verification failures dominate over raw coding failures.
- Review quality: (INFERENCE) Do not accept compile-level checks as review: ChatDev's reviewer passed a chess program that was runtime-broken. Reviewers in the Army should execute tests/game rules or run the app, not just read the diff.

## Validity
- Evidence grade: A (peer-reviewed NeurIPS 2025 D&B; controlled annotation with human IAA, LLM-annotator agreement, cross-system generalization; case-study interventions with 6 repetitions and Wilcoxon tests).
- Threats (contamination, not budget-matched, toy tasks, single model family, ...): ProgramDev tasks are "relatively straightforward" and programming-challenge-like (p.21), not repo-level — coding findings may not transfer to large codebases; the SWE-Bench Lite slice is only 30 traces via one framework; interventions are small (30-200 problems, one framework each); annotator labels are o1-generated at scale (LLM-as-judge conflations possible — moderate inter-mode correlations up to 0.63); prevalence percentages mix wildly different benchmarks so cross-system comparisons are illustrative, not controlled (Fig 4 caption admits this); the taxonomy itself is the paper's main artifact.
