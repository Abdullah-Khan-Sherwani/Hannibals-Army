## Setup
- Tasks / benchmarks (coding? repo-level? research? planning?): HotpotQA, Bamboogle, Natural Questions, BrowseComp+, HumanEval, MBPP, MATH: seven listed benchmarks despite occasional “eight” wording (§4.1/Table1, pp.6–7). Topology/self-generation evidence, not repository coding-team study.
- Models used (per role): generator/implementor/rectifier are separately specialized Qwen3-8B policies, LoRA rank8/alpha16. Executor pool GPT-4o/4o-mini, Qwen2.5-72B, Qwen3-14B, QwQ32B. Later unseen-pool experiments add Qwen3-Coder, GPT-5-mini, Gemini2.5-Pro (§4.1–4.3).

## Topology tested
- Depth: 0 = single agent · 1 = orchestrator → workers · 2 = orchestrator → sub-orchestrators → workers · recursive: meta-team generates/configures a target MAS and can repair it during execution. Two conceptual levels (meta/target), not an experiment varying command depth1/2/3. “Recursive self-generation” does not demonstrate unbounded nested management.
- Width (workers per orchestrator) and how it was varied: target graph size adapts per query; no controlled width sweep. Training tree uses4 generated templates×2 instantiations; these are offline samples, not eight simultaneous workers (§4.1, p.7).
- Roles (planner, implementer, verifier, reviewer, integrator, router, ...): generator architects roles/tools/protocol, implementor fills model placeholders (NOT task-code implementer), rectifier repairs workflow on failure/budget trigger; target MAS may contain planner, retriever, programmer, reviewer, aggregator.
- Communication / handoff format; who can write code/files: Python Workflow class in graph XML tags; generator writes workflow code, implementor assigns backbones, rectifier can change execution code/configuration. Execution uses typed operators; no worktree ownership or sole-integrator experiment (Appendix B–D).

## Findings (quote numbers with table/figure/page refs)
- Depth (when does more depth help or hurt?): generated MAS² reaches89.3 HotpotQA versus ScoreFlow86.0/MaAS83.6; BrowseComp+19.7 versus best listed baseline CoT16.1; MATH71.3 versus MaAS70.1 (Table1, p.7). These bundle training, adaptation and heterogeneous execution; not causal depth gains.
- Width (where does adding workers plateau?): unmeasured. Example workflows use multiple candidates on harder problems and cheaper paths on simpler ones (Figure5, p.9; Appendix C).
- Role → model placement (which tier where, cost vs quality): trained8B meta-agents successfully organize larger executors. Examples use cheaper retrieval/candidate generation and stronger synthesis/review, but not matched seat-swap experiments. Appendix C also uses4o-mini reviewers in QA; no universal “reviewer must be strongest” result.
- Verification / review effects: no rectifier drops MATH71.3→64.7 and MBPP~85.2→81.7; untrained generator gives MATH63.1, untrained implementor65.3 (Figure4, p.9). Rectifier is workflow recovery, not independent final factual verification. MBPP main table85.1 versus ablation85.2 is inconsistent.
- Cost / tokens / latency: base MAS² MATH71.3 at$0.74, Bamboogle67.2 at$0.15; stronger unseen-pool mix MATH90.6 at$16.14/Bamboogle84.0 at$2.73 (Table2, p.8). Thus quality gains can cost substantially more; no latency scaling. Figure3 reports near-equal-cost NQ79.1 versus ScoreFlow76.4.
- Failure modes observed: tool/API/schema failures; accepted Appendix D.3 raises search budget3→6; D.4 upgrades final generator and changes prompt together. D.2 recovers by bypassing failed reviewers; D.1's illustrated post-call fallback would not catch the shown in-call exception. Treat cases as illustrations, not verified general recovery guarantees.

## Implications for Hannibal's Army (label each as INFERENCE)
- Depth-1 design: INFERENCE: make explicit workflow failure/overrun triggers and bounded repair, rather than blindly rerunning the same team.
- Depth-2 design: INFERENCE: specialize planning/configuration/recovery above workers when tasks justify it; this paper does not establish that sub-orchestrators improve equal-budget outcomes.
- Which agent/model type goes in which seat: INFERENCE: a trained smaller coordinator may suffice; assign larger models to measured hard synthesis/judgment steps, without inferring vendor seats from selected examples.

## Validity
- Evidence grade: A = peer-reviewed + controlled · B = preprint + controlled · C = case study / uncontrolled: A, component ablations; weaker for depth/seat causality.
- Threats (contamination, not budget-matched, toy tasks, single model family, ...): model-pool/budget confounds, public benchmark contamination, no depth sweep; missing clear sample sizes/splits in experimental setup. Abstract19.6 improvement is HumanEval97.0 minus average vanilla77.4 in Table1, not gain over strongest baseline96.3. Do not repeat it as a universal SOTA margin.
