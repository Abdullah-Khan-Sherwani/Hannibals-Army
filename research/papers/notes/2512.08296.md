## Findings (quote numbers with table/figure/page refs)

- Depth (when does more depth help or hurt?): topology comparisons cannot isolate depth. Finance centralized 0.631 versus SAS 0.349 (+80.8% relative); PlanCraft centralized 0.282 versus 0.568 (−50.3%); Independent 0.170 (−70.0%) (§4.2, pp.13–14). Decentralized gains: BrowseComp +9.2% (0.347/0.318); WorkBench +5.6% (0.664/0.629). SWE SAS/centralized: v3 0.522/0.506; **J** 0.488/0.475. Terminal SAS/centralized: v3 0.344/0.278; **J** 0.312/0.250 (J p.1159).
- Width (where does adding workers plateau?): Flash centralized peaks near 7; curves are nonmonotonic, not a universal 3–4-worker ceiling (Fig.5, p.23). **J** Fig.3 specifies BrowseComp-Plus, 100 tasks/cell, single runs without error bars (p.1165).
- Role ? model placement (which tier where, cost vs quality): stronger workers beat stronger orchestrators: GPT 0.21 versus 0.19; Sonnet 0.42 versus 0.37; Gemini 0.23 versus 0.18. Yet all 7 centralized mixed teams trail strong homogeneous baselines (mean −12.6 percentage points); 6 decentralized mixes average +2.0 points (Table 12, p.42). Fig.4’s Sonnet improvement claim conflicts with that table; J Extended Data Fig.2 directs readers to canonical Supplementary Table S7.
- Verification / review effects: communicating architectures report 22.7% factual-error reduction (95% CI 20.1–25.3%); centralized trace amplification 4.4× versus Independent 17.2×, **not task failure multipliers** (§4.4, pp.21–23). No isolated reviewer intervention.
- Cost / tokens / latency: SAS/centralized/hybrid average 7.2/27.7/44.3 turns; overhead 285%/515% (Table 5, p.20). These are turn increases, not larger token ceilings. Dollar-cost coverage excludes coding benchmarks (Fig.3, p.16); no comparable wall-clock latency result.
- Failure modes observed: unnecessary sequential-task decomposition, context omission, numerical drift, state/message conflicts; hybrid coordination failures 12.4% versus centralized 1.8% (p.23).

## Implications for Hannibal's Army (label each as INFERENCE)

- Depth-1 design: **INFERENCE** — benchmark a small verified team against a strong SAS at equal total budget; delegate separable work.
- Depth-2 design: **INFERENCE** — treat generals as an untested overhead hypothesis; require measured improvement before adding management layers.
- Which agent/model type goes in which seat: **INFERENCE** — protect worker capability; retain a capable verifier/integrator. Test cheaper coordinators locally; this paper establishes no current-brand seat ranking.

## Validity

- Evidence grade: A = peer-reviewed + controlled ? B = preprint + controlled ? C = case study / uncontrolled: **A**, peer-reviewed controlled comparisons; hierarchy-depth and reviewer-seat claims remain unsupported.
- Threats (contamination, not budget-matched, toy tasks, single model family, ...): six benchmark clusters, reconstructed capability indices, architecture-level metric constants, 20-task coding CIs typically ±20 points, shared state. **J**: only baseline coefficient survives both cluster/Holm corrections; baseline×agents robust p=0.105, tools×efficiency p=0.205, baseline-scaled errors p=0.030 (Supplementary Tables S9–S11). Thus ~45% cutoff is a selection heuristic (94% sign-match across 16 validation cells), not a confirmed universal coefficient. Within-domain R²=0.373/0.413 and 87% architecture selection do not transfer automatically: LODO R²=−2.09 (pp.1166–1167); frontier extrapolation incorrectly prefers Hybrid (v3 Appendix B, p.37). V3’s message-density fit R²=0.68 excludes zero-message systems; J includes them and reports R²=0.018, p≈0.07 (p.1165). Contamination untested; no experiment reproduction.
