## Setup
- Tasks / benchmarks (coding? repo-level? research? planning?): Repo-level coding verification — SWE-Bench Verified, 500 problems, K=16 independent rollouts per problem; verifier's job is to rank/select the best candidate patch (parallel test-time scaling, BEST@K). Patch resolution judged by hidden F2P/P2P tests.
- Models used (per role): Generator models: Qwen3-32B (max 30 turns) and Qwen3-Coder-30B-A3B (max 50 turns), temp 1.0, SWE-Agent scaffold. Expert rubric agent / agentic test generator: Claude Sonnet-4.5 (30-turn budget). Judge for grading: GPT-5 (low reasoning) by default; judge sensitivity ablated across GPT-5-mini → high. Rubric-generation model ablated across Opus-4.5, Sonnet-4.5, Gemini-3-Pro, GPT-5, Meta-CWM, Qwen3-Coder-30B, Qwen3-32B.
- Baselines (single agent? flat team? budget-matched? yes/no + how): Verifier-vs-verifier comparison with identical generators/rollouts and identical judge model where applicable: Oracle Pass@16 (upper bound), Random, Self-Consistency, Patch Classifier (R2E-Gym-style), Agentic Tests (test generation + execution), Agentic Patch Similarity (proxy reference patch). Cost accounting per method (Table 4, p.13) — effectively budget-aware.

## Topology tested
- Depth: 1 — a single expert verifier agent (rubric agent) interacts with the repo to produce a verification artifact; scoring of patches is then execution-free by an LLM judge. Separates artifact generation (agentic, done once per instance) from scoring (per rollout, cheap).
- Width (workers per orchestrator) and how it was varied: Rollout width K varied 1→16 for the generator; verifier compares selection quality as K grows (Fig 2 right). Repeats: 100 trials when K<16.
- Roles (planner, implementer, verifier, reviewer, integrator, router, ...): Verifier = rubric agent (artifact author) + LLM judge (grader). No planner/integrator. Rubric axes: File Change (4-8 items), Spec Alignment (3-6), Integrity (3-6: no-cheating — no test weakening, no mass renames, no dependency churn), Runtime (3-6). Items weighted 1/2/3; score = weighted binary aggregate (Fig 1, §3.1, pp.2-3).
- Communication / handoff format; who can write code/files: Handoff artifact is a rubrics.yaml file (structured criteria) written by the rubric agent into the repo at generation time; judges only see problem statement + rubric + final patch (deliberately NOT the agent's thinking trace, to reduce verifier hacking, §3.3 p.4). Candidate patches are responses.diff; no execution needed for scoring.

## Findings (quote numbers with table/figure/page refs)
- Depth: One expert verifier agent + execution-free scoring beats execution-based Agentic Tests: BEST@16 40.6 vs 33.6 (Qwen3-32B) and 54.2 vs 49.0 (Qwen3-Coder); vs Oracle 51.4 / 65.6 ceilings; Random 22.6 / 39.6 (Fig 2, p.4). Gains over best verifier baselines: +3.5 (vs Patch Classifier 37.1) and +4.0 (vs 50.2) pts; remains ahead as K scales.
- Width: Scoring quality grows with K; all verifiers converge toward Oracle Pass@16 as K grows, but rubric separation persists at every K sampled (1-16) — rubric's advantage "not confined to a single operating point" (§4.1, p.4-5).
- Role → model placement: Rubric-agent model capability matters: frontier models (Opus-4.5, Sonnet-4.5, Gemini-3-Pro) ~54% BEST@16; open 30B-class (Qwen3-Coder-30B, Meta-CWM) ~45%; non-coding Qwen3-32B ~43% (Fig 6a, p.8). More capable models write more rubrics (Sonnet-4.5 >20 items/instance, ~2× Qwen3-32B) and align better with human GT patches (Opus-4.5 rubric mean score on GT patches 0.8658 vs Qwen3-32B 0.6729, Table 3, p.13). Scaffold-format compliance: Sonnet-4.5 97.8% parseable / Gemini-3-Pro 96.8% vs Qwen3-32B 74.6% (18.2% parse errors) and Meta-CWM 69.4% + 29.8% missing (Fig 9, p.16). BUT judge-capability barely matters: GPT-5-mini 52.6 → low 54.2 → medium 54.3 → high 55.0 (±2.2) (Table 2, p.9) — cheap judges suffice when rubrics are atomic/self-contained.
- Verification / review effects: Rubric scores align with GT tests: ROC-AUC 0.886, PR-AUC 0.722 vs F2P pass/fail; GT-pass rollouts score 0.85-1.0, GT-fail spread ~0.4-0.5 — graded (denser) signal, not binary (Fig 3, p.5). Utility audit: when rubrics agree with tests, 78% of judgments are high-utility; when rubrics reject a test-passing patch, 54% of those rejections flag plausible under-tested problems (root cause missed 17.5%, missing edge cases 15.1%) vs 46% low-utility modes (over-specified 8.7%, redundant 8.5%) (Fig 5, pp.6-7). Rubric flakiness: Sonnet-4.5-generated rubrics 2% non-deterministic across 5 repeated judgements; Qwen3-32B 9% (§A.4, p.14).
- Cost / tokens / latency: Per-instance total cost (artifact + grading 16 rollouts): Patch Similarity $0.736, Tests $0.515, Rubrics $0.293 — the best-performing verifier is also the cheapest (Table 4, p.13). Artifact-generation calls: rubrics 22.9 API calls vs patch sim 48.5 and tests 29.2. SFT: rubric-generation SFT (2,000 Sonnet-4.5 trajectories, 2 epochs on 4×8 H100) beats patch-classifier SFT at equal base model (Fig 7, p.9).
- Failure modes observed: Non-agentic rubrics (no repo access) lose 4.0 pts (Qwen3-32B rollouts) / 1.4 pts (Qwen3-Coder) — grounding matters (§5.2, p.9). Low-utility rubric failure modes: over-specification, redundancy, rubric-test mismatch, spec conflicts (46% of over-strict rejections; Fig 5b). Cross-file reasoning gaps and runtime issues remain the hard categories (GT-fail patches still score well on Integrity; Fig 4, p.6). Execution-free scoring risk: sensitive to surface cues (noted gap in literature, §2.1). Test-based verification has its own toxicity/coverage limits (Agentic Tests only 33.6/49.0). Hybrid aggregating tests+rubrics beats either alone (§A.5).

## Implications for Hannibal's Army (label each as INFERENCE)
- Depth-1 design: (INFERENCE) Verification can be two-stage and much cheaper than execution-per-candidate: one strong verifier agent writes a repo-grounded rubric checklist once (Sonnet-class, ~23 calls, $0.25), then a cheap judge scores every candidate patch against it (~$0.003/rollout). For the Army this maps to: reviewer seat produces machine-checkable acceptance criteria from the spec + repo before workers start; the criteria become the observable acceptance in worker specs; grading can even be Flash-tier.
- Depth-2 design: (INFERENCE) Sub-orchestrators should own rubric/verification-artifact generation for their slice (it requires repository interaction and judgment), while mechanical scoring across many worker outputs is centralizable and near-free. Don't ask the cheapest tier to author rubrics (Qwen3-32B: 74.6% parseable, 0.67 GT alignment) — authoring is a strong-model job; grading is not.
- Which agent/model type goes in which seat: (INFERENCE) Verifier/author seat = frontier coding model when available; implementers = whatever generates rollouts; grader/judge = cheap model (GPT-5-mini loses only 1.6 pts vs high-reasoning). This is the cleanest model-placement evidence in my reading: capability where judgment is created, frugality where it is applied.
- Anti-gaming: (INFERENCE) Score only spec + artifact + final patch, never the worker's self-narration/thinking traces — reduces hacking and matches the Army's "reviewers audit diffs, not stories". Integrity axis (no test weakening, no mass renames, no dep churn) is a ready-made checklist for the user's reviewer generals; the 62%-of-false-approvals pattern from SWE-Review is exactly what an Integrity axis + independent tests catch.

## Validity
- Evidence grade: B (preprint, but controlled: fixed generators/rollouts, same scaffold/sandbox, Oracle/Random references, 100-trial averaging for K<16, cost accounting, utility audit on 100 instances, flakiness study).
- Threats (contamination, not budget-matched, toy tasks, single model family, ...): Single benchmark (SWE-Bench Verified, Python/PyTest-style repos); rubric generation and scoring both use GPT-5 judges — judge bias unquantified beyond flakiness; gold tests used to define correctness (some "test-passing but rubric-rejecting" patches may be genuinely fine — 46% low-utility rejections); best-of-K selection only evaluates verifiers, not end-to-end agent teams; artifact cost counts exclude retries beyond parse failures; 16 rollouts × 500 problems at temp 1.0 is a single sampling campaign per generator.
